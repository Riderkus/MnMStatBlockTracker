# Stat Block Tracker

A small Progressive Web App (PWA) for tracking Mutants & Masterminds stat blocks
and conditions. Plain HTML, CSS and JavaScript. No build step, no backend, no
dependencies. Runs in any browser and installs to a phone's home screen.

## Files

| File | What it does |
|------|--------------|
| `index.html` | The page skeleton: top bar, sidebar list, editor form. Repeated parts are generated by `app.js`. |
| `style.css` | All styling. Colours live in CSS variables at the top. Mobile-first with a two-column layout from 820px. |
| `app.js` | All behaviour: data model, saving to localStorage, drawing the list and form, export/import of `.json`, the rules popup. |
| `reference.js` | Data only: the rules sections of the Reference popup. Edit rules text here. (The Advantages, Powers and Complications tabs come from `samples.js`.) |
| `samples.js` | Data only: the skills, advantages, powers and complications offered by the "+ From the book" buttons. |
| `sw.js` | Service worker. Caches the files so the app opens offline. |
| `manifest.json` | Tells the OS how to install the app (name, icons, colours). See below. |
| `icon.svg` | The app icon as vector art. |
| `icon-192.png`, `icon-512.png` | Flattened copies of the icon for platforms that need PNG (iOS home screen, Android install). |

## How data is stored

- Everything lives in one JavaScript object: `{ version: 1, blocks: [...] }`.
- Every edit updates that object and, 300 ms later, writes it to the
  browser's `localStorage` under the key `statblocks.v1`. Nothing is sent anywhere.
- **Export** writes the same object to a file. The name is today's date,
  `statblocks-2026-10-17.json`, unless the data was imported from a file: then
  that file's name carries on with a counter, so `heroes.json` in gives
  `heroes (1).json`, then `heroes (2).json`, and `heroes (2).json` in gives
  `heroes (3).json`. (The name and counter are kept as `file` next to
  `blocks`.) On phones Export opens the share sheet so you can save to Files
  or OneDrive.
- **New file** empties the app for a clean slate, after asking when there
  are blocks to lose, and forgets the linked Save file so the next save goes
  to a new one (on a PC the file dialog opens right away). The old blocks
  and file link come back with Undo for a few seconds.
- **Save** (Chrome and Edge on a PC only; the button is hidden elsewhere)
  writes to the same `.json` file every time instead of making a new one. The
  first press opens a file dialog, suggesting the imported file's name so you
  can overwrite it; later presses write silently, and after that first press
  every edit is written to the file as well, so the file always matches the
  app. The file is remembered across reloads (as a handle in the browser's
  IndexedDB); the browser just asks once per session, on the first press, for
  permission to write it. Clearing the site's data forgets the file.
- **Import** reads such a file and asks whether to replace your current blocks
  or merge them. When merging, a block with the same id wins if it was edited
  more recently.

Each block looks like this:

```json
{
  "id": "9d7d3e56-666c-4cef-a154-407996578592",
  "type": "sheet",
  "name": "Doc Nova",
  "pl": 12,
  "heroPoints": 1,
  "minions": { "count": 1, "down": 0 },
  "portrait": "",
  "identity": { "realName": "Nora Vale", "status": "Secret", "player": "Sam", "occupation": "Physicist", "group": "", "base": "Emerald City", "gender": "F", "age": "31", "height": "5'9\"", "weight": "140 lbs", "eyes": "Brown", "hair": "Black" },
  "background": { "appearance": "", "personality": "", "history": "" },
  "abilities": { "STR": 8, "STA": 0, "AGL": 0, "DEX": 0, "FGT": 0, "INT": 0, "AWE": 0, "PRE": 0 },
  "defenses": { "Dodge": 0, "Parry": 0, "Fortitude": 0, "Toughness": 12, "Will": 0 },
  "initiative": 0,
  "conditions": ["Dazed", "Unaware"],
  "conditionDetails": { "Unaware": "Visual, Tactile" },
  "bruises": 2,
  "pp": { "earned": 3, "other": 0 },
  "powers": [{ "name": "Flight", "rank": 6, "desc": "Wings; Subtle", "cost": 12, "perRank": 2 }],
  "skills": [{ "name": "Perception", "ability": "AWE", "ranks": 6 }],
  "advantages": [{ "name": "Evasion", "rank": 2, "note": "" }],
  "offense": [{ "name": "Unarmed", "bonus": 10, "range": "Close", "kind": "damage", "damage": 2, "resist": "Toughness", "effect": "" }],
  "complications": [{ "name": "Motivation: Justice", "note": "" }],
  "equipment": [{ "name": "Pistol", "cost": 8, "note": "Ranged Damage 3" }],
  "notes": "",
  "updated": 1760702400000
}
```

`portrait` is an optional picture: the chosen image is cropped to a square,
shrunk to 256 px and stored as a small JPEG data URL, so it travels with
exports and needs no file access. `type` is one of `sheet` (full character sheet), `block` (the standard stat
block, and the default for saves that predate kinds) or `minion` (the short
block for goons). It only changes which sections the editor shows: every block
carries every field, so switching kinds never loses anything. `heroPoints`,
`identity` and `background` are shown for sheets only.

## manifest.json, field by field

JSON files cannot contain comments, so the explanation lives here instead.

| Field | Meaning |
|-------|---------|
| `name` | Full app name, shown on the install prompt and splash screen. |
| `short_name` | Shorter name used under the home-screen icon where space is tight. |
| `description` | Shown in some install dialogs and app listings. |
| `start_url` | The page to open when the installed app is launched. |
| `scope` | Which URLs count as "inside the app". Navigating outside the scope opens the normal browser. `./` means this folder. |
| `display` | `standalone` hides the browser's address bar so it feels like a native app. Other values: `browser`, `minimal-ui`, `fullscreen`. |
| `orientation` | `any` lets the app rotate freely. Could be `portrait` to lock it. |
| `background_color` | Colour of the splash screen while the app loads. Matches `--bg` in `style.css`. |
| `theme_color` | Colour of the status bar / title bar on Android. Matches `--accent` in `style.css`. |
| `icons` | List of icons at different sizes. The SVG covers "any" size; the PNGs are for platforms that require raster images. `purpose: any` means a normal icon (as opposed to `maskable`, which lets the OS crop it into its own shape). |

## Running it

Service workers and some browser APIs only work over `http://localhost` or
`https://`, so don't open `index.html` by double-clicking it. Start a tiny
server in this folder instead:

```
python -m http.server 8080
```

Then open <http://localhost:8080> on the PC. To try it on a phone on the same
wifi, use the PC's local IP address, e.g. `http://192.168.1.20:8080`.

To install to a phone's home screen (and get offline mode), the app needs to be
served over HTTPS. GitHub Pages is a free way to do that.

If you serve the folder with VS Code's Live Server instead, note that it
reloads every open copy of the page whenever a file in the folder changes,
which includes the `.json` file the Save button writes. `.vscode/settings.json`
in this folder tells Live Server to ignore `.json` files for that reason.

## Making changes

- **Add a field:** add it to `blankBlock()` in `app.js`, add an input with a
  matching `name=""` to the form in `index.html`, and add it to the list of
  text keys in `renderEditor()` if it is free text.
- **Attacks:** an offense entry has a `kind`, `damage` (a Damage effect, DC
  15 + rank) or `effect` (anything else, such as an Affliction, DC 10 +
  rank), its rank (kept under the key `damage` for both), what it is
  `resist`ed by (Toughness, Fortitude, Will, Dodge or nothing) and an
  optional `effect` text. The play view shows "Damage 3" or "Rank 5" with
  the resistance DC. Switching the kind swaps the default resisting defense
  (Toughness for damage, Fortitude otherwise). A save without a kind is
  Damage unless its rank was resisted by something other than Toughness. A save from before these fields existed gets the
  damage read out of its effect text ("Damage 3" becomes damage 3, Toughness,
  with the text cleared) on load.
- **Reordering:** every list row (powers, skills, advantages, equipment,
  attacks, complications) has a grab handle next to its remove button. Drag
  it with the mouse or a finger, or focus it and press the arrow keys; the
  entry moves in the block's array, so the play view follows.
- **Play view:** the Play button in the editor shows the open block as a
  one-screen sheet for the table (`renderPlay` in `app.js`, section 5c):
  abilities and defenses as big boxes (Dodge and Parry with their defense
  class, and adjusted for Vulnerable, Defenseless and bruises), counters for
  bruises and hero points, the active conditions as pills with "+ Condition"
  and Clear, and tabs for attacks (with the defense they are checked against
  and the effect's resistance DC), powers, skills, advantages, equipment,
  complications, notes and background. Everything else is read-only there;
  Edit goes back to the form. The view mode is remembered under
  `statblocks.view` in localStorage. On a touch screen a sideways swipe over
  a tab's contents moves to the next or previous tab.
- **Undo:** deleting a block (after its confirm box) or clearing its
  conditions shows an Undo bar for eight seconds (`offerUndo` in `app.js`).
- **Portrait:** the small dashed square left of the name picks an image.
  With a picture in place a tap enlarges it and the cross (on hover) removes
  it; to swap the picture, remove it and pick again. The image is stored as
  text inside the block (a base64 JPEG data URL, about 8 KB), so it is part
  of every export and Save file and needs no separate image file.
- **Minions and bruises:** a minion never takes a bruise (any failed
  resistance check gives it the worst degree, p. 245), so the Bruises field
  is hidden for minions. Instead one minion block can stand for a group:
  `minions.count` is how many (the Number field in the editor, or the
  Minions counter in the play view) and `minions.down` how many are out,
  counted with the Down counter in the play view; Up shows the rest. The
  list shows "Minion ×4" and a "1 of 4 down" badge. Clear brings them all
  back up.
- **Save dot:** while a `.json` file is linked but has not received the
  latest changes (before the first Save press of a session, or after a
  failed write), the Save button shows an orange dot.
- **Kind filter:** the dropdown after the sort order shows only sheets,
  blocks or minions; the choice is kept under `statblocks.kind`.
- **Sort orders:** the dropdown beside the search box offers the entries of
  `SORTS` in `app.js` (name, kind, power level, last edited, "in trouble" =
  most bruises and conditions first). Add one there and as an `<option>` with
  the same value in `index.html`. The choice is kept under `statblocks.sort`
  in localStorage, separate from the blocks.
- **Kinds of block:** `TYPES` in `app.js` lists them (`sheet`, `block`,
  `minion`). A section in `index.html` with `data-types="sheet block"` is shown
  for those kinds only; one without the attribute is shown for all. "+ New"
  asks for the kind; the dropdown next to PL changes it later. For minions
  the Notes box is relabelled "Traits & notes" and the sidebar skips the
  overspend badge, since they have no power point section.
- **Number ranges:** abilities, defenses and initiative run -999 to 999; PL
  and bruises 0 to 999. The limits are in `RANGES` at the top of `app.js`; the
  inputs use them as min/max, values typed or imported outside them are
  clamped, and a field left empty becomes 0. On touch screens a signed field
  shows a +/- button while you are typing in it; one tap flips the sign.
  Phone keypads often lack a minus key, which is what this is for.
- **Text boxes** (skills, notes, power descriptions...) size themselves to
  their text; see `fitTextarea` in `app.js`. Nothing about their size is saved.
- **Lists:** skills, advantages, offense, complications and powers are arrays
  of small objects (shapes above). A save from before they were lists holds
  free text, which is split into entries on load as best it can be.
- **Power points:** the total is PL x 15 plus `pp.earned`, the points the GM
  has awarded (an older save's `pp.total` override above the base becomes
  `earned` on load). Everything but `earned` and `other` is computed (see
  `computePP` in `app.js`): abilities and defenses from the stat boxes,
  skills (1 per 2 ranks), advantages (1 per rank) and powers (each power's
  `cost`) from their lists. Old lump sums under `pp.powers`, `pp.skills` or
  `pp.advantages` are moved into `other` on load when the list gives nothing.
- **Equipment:** the Equipment section is shown only while an advantage whose
  name starts with "Equipment" is in the list; its points are that
  advantage's rank x 5 (see `computeEP` in `app.js`).
- **From the book:** the picker lists come from `samples.js`. A power picked
  from the book carries `perRank`, so its cost follows its rank until you
  edit the cost by hand.
- **Add a condition / ability / defense:** add the string to the matching
  array at the top of `app.js`. The form and badges update themselves.
  If the new condition makes another redundant, add it to `SUPERSEDES`; if it
  needs a specifier (which sense, which trait), add it to `CONDITION_DETAILS`.
- **Change colours:** edit the variables in the `:root` block at the top of
  `style.css`. The dark-mode block below it overrides them when the OS is dark.
- **Change fonts:** `--font-display` (labels, buttons, numbers) and
  `--font-body` (long text) are variables in the same `:root` block. The
  display stack starts with Agency FB, which ships with Windows, and falls back
  to Teko, which `index.html` loads from Google Fonts for phones and Macs.
- **Edit the rules reference:** the rules tabs of the Reference popup come from
  `reference.js`. Each entry is `{ name, text, rows?, condition?, verify? }`;
  the format is explained at the top of that file. The current text was
  checked against the Deluxe Hero's Handbook and cites page numbers. If you
  add an entry you are unsure of, give it `verify: true` to show a red
  "check vs book" tag until you have compared it.
- **After editing any file:** bump `CACHE_VERSION` in `sw.js`, otherwise
  installed copies keep showing the old version.

## Tests

The `tests/` folder holds Playwright scripts that drive the app in a headless
Chromium, on a desktop and a phone-sized viewport, and print what they find.
They are not part of the installed app. To run them:

```
cd tests
npm install                      # once: the Playwright package
npx playwright install chromium  # once: the browser it drives
node run.mjs                     # every test, or: node run.mjs play swipe
```

The runner starts `python -m http.server` on port 8765 in the app folder,
runs each script and stops the server. Screenshots land in `tests/shots/`.

## Rules text

The reference entries and the sample skills, advantages, powers and
complications are summarised from the Mutants & Masterminds Deluxe Hero's
Handbook, which is Green Ronin Publishing's. This is a fan-made tool for
personal use at the table, not an official product; if you publish the app,
keep the book itself out of the published folder and be aware that the
publisher can ask for the summaries to be taken down.
